Quantum Docs Assistant: Cited, Code-Checked RAG over Qiskit and PennyLane

Quantum AI · Python, rank-bm25, scikit-learn, Qiskit 2.6.2, PennyLane 0.45.1 · 14,648 chunks from 1,893 documentation pages

An assistant that answers Qiskit and PennyLane questions using only their official documentation. Every answer cites its sources, the code example it returns is executed against the installed library versions before it's shown, and questions the docs don't cover are refused rather than guessed.

Demo

About the demos: both clips are rendered from the assistant's real output, saved in results/demo_answers.json. Answers use the default extractive mode (sentences picked from the docs, not written by a model). An optional Claude mode writes answers from the same numbered sources, but it could only be tested with a mock client in the environment this was built in.

Why this design

  1. Quantum SDKs change fast. Qiskit 1.0 removed execute, 2.0 removed Pulse, and PennyLane's docs now write qp.. So the corpus is pinned to the installed versions: Qiskit 2.6.2 API docs, qiskit-ibm-runtime 0.52.1, and PennyLane v0.45.1 docs plus the installed package's docstrings.
  2. "Looks right" isn't enough for code. Candidate examples are executed in an isolated subprocess, in rank order, and the first one that runs is shown. The checker caught a migration-guide snippet that imports the removed execute().
  3. A refusal beats a confident wrong answer. The refusal signal requires the question's key terms to appear together in a single retrieved chunk, with unseen terms weighted heavily. The threshold was calibrated on a dev split and reported on a held-out split.

Refusal

On the test split it answered 29 of 30 in-scope questions and refused 7 of 8 out-of-scope ones. Across all 76 questions there was one miss each way. A question about Quirk's drag-and-drop editor was answered from IBM Quantum Composer's page, which is also a drag-and-drop editor. "Prepare a state from a vector of amplitudes" was refused at coverage 0.47, even though the retrieved page was relevant.

Method

  • Ingestion: Qiskit guides, tutorials and API reference (MDX and notebooks; API pages split into one chunk per method), plus PennyLane RST guides and docstrings. JSX, RST roles and links are stripped, code is kept, and every chunk records its section and deep link.
  • Retrieval: BM25 with an identifier-aware tokenizer (QuantumCircuit → quantum, circuit; qml.expval → expval) and LSA (TF-IDF + SVD), fused with reciprocal rank fusion. Questions are routed by framework, and a document-type prior favors guides and API pages over long tutorials.
  • Answers: extractive by default (the top-ranked sentences, each cited), with an optional Claude mode restricted to the numbered sources.
  • Code execution: isolated subprocess with a 60 s timeout. Doctest blocks are converted, standard imports are added, and earlier cells from the same page run as best-effort context. Examples that need an IBM account, network or an optional package are skipped rather than failed.
  • Evaluation: 60 in-scope questions labeled with their gold documentation pages, plus 16 out-of-scope questions. All tuning used the dev split; numbers above come from the held-out test split unless stated. 11 pytest checks.

Limitations

  • Extractive answers read like excerpts, not explanations. The LLM mode addresses this, but it was only tested with a mock client.
  • 76 labeled questions give wide error bars.
  • A corpus-trained semantic model can't match pretrained embeddings on paraphrases.
  • A passing example ran without errors; its output wasn't checked.
